OpenDRIVE Spec Atlas

ASAM OpenDRIVE 1.7.0 read in full, checked against 1.8 and 1.9.0: every formula, rule, use case and right or wrong modelling choice, as the reference OdrForge is built against.

Frozen plan

Built on the complete study: ASAM OpenDRIVE 1.7.0 (full text, 123 figures), 1.9.0 (94 pages, 184 figures, Annex D and F), 1.8.0 (archived text) and the ASAM Junction Guideline 1.0.0 (16 pages, 71 figures). Every step below is implemented, tested and gated before the next starts.

0. Foundations

  1. Two output profiles. carla: OpenDRIVE 1.4 vocabulary (what LibCarla reads). standard: OpenDRIVE 1.8 / 1.9 full model. One internal model; each feature declares how it is written per profile, and a 1.8-only feature has a documented 1.4 substitute (e.g. walking → sidewalk, direct junction with overlapZone → common junction, crossPath → crosswalk object). Spec ch. 5 Backward compatibility; Junction Guideline 1.7 mapping
  2. Spec references in the code. Every function that implements OpenDRIVE behaviour states its source in one line: version, chapter and section, rule id and backward compatibility, e.g. // OpenDRIVE 1.9 §11.6 lane linkage, road.lane.link.zero_width_at_start (1.7.0); carla profile: same. A rule catalogue (generated from this atlas) maps each rule id to the function that implements it and the check that verifies it.
  3. Clean code. Small functions named after what they do, one responsibility each, readable without comments; the spec reference line is the comment that matters.
  4. The gate is the standard. Annex F checker rules that apply to generated maps plus Annex D smoothness (position, heading, height and roll continuous wherever drivable lanes meet) become exact checks; both profiles must pass XSD (1.4 / 1.8.1), CARLA and esmini on the six reference areas, with zero violations.

1. Junctions by the Junction Guideline

The structure (own id, incoming roads, connecting roads, lane links) is right today; placement, extent, type and contents are not.

  1. Outline and arm cuts. One common junction per real intersection (multi-arm built as one, never chained T and X junctions), as small as possible and as big as necessary: each arm is cut where its curb return starts, before any crosswalk; arms keep junction = -1; junctions never overlap. Guideline §6; 1.9 §12.2, junctions.no_overlap, not_only_two
  2. Connecting roads per permitted relation. One per lane movement from turn:lanes (natural flow when untagged), from arm end to arm end with matching heading, reference line in driving direction, contactPoint at the connecting road end; lane links only on connecting-road lanes; every incoming drivable lane linked, every outgoing lane fed; outgoing-only one-way arms are not incoming roads. 1.9 §12.3, 12.4; Guideline §6
  3. Curbs and sidewalks through the junction. Arms carry driving, curb (~0.15 m) and walking lanes; the connecting roads that run along the outline carry the curb and walking lanes round the corner (replacing the separate curb-return roads), with laneOffset and an outward-shifted reference line on wide turns so no inner edge gets a negative radius. Lowered curbs at crosswalks by lane height. Guideline §6; 1.9 §11.8 lane height
  4. Crosswalks. Inside a junction: a road of the junction with one walking lane and a crossPath (standard); a crosswalk object (carla). Mid-block: virtual junction on the uncut road plus crossPath (standard); crosswalk object (carla). 1.9 §12.5, 12.7; Guideline §10
  5. Motorway entries and exits. Direct junction, one cut: non-overlapping entry cut at the gore (onRamp / entry lanes); overlapping exit cut where the exit begins, exit lane then offRamp in a new lane section, overlapZone on the one overlapping pair (standard); common junction with the same lane mapping (carla). Common junction whenever traffic crosses or more than one lane overlaps. 1.9 §12.6; Guideline §7
  6. Slip lanes. Their own one-way roads (slipLane / driving) between direct junctions at every diverge and merge; the central crossing is the only common junction; slip relations not repeated inside it. Guideline §8
  7. Roundabouts as one junction per arm with the ring as roads, in a junction group of type roundabout; level crossings as crossing junctions (standard); driveways as virtual junctions (standard), common junctions (carla). 1.9 §12.7, 12.8, 12.13
  8. Junction surface (standard): junction reference line, counter-clockwise boundary of lane / joint segments, elevation grid from the terrain with transition lengths. 1.9 §12.9 – 12.11
Done when the junction audit is zero on all six areas in both profiles: no two-road junction, no overlapping junctions, no incoming lane without a path, no unfed outgoing lane, no crossing movements within an approach, curbs and sidewalks continuous round every corner.

2. Lanes to the letter

  1. A lane section wherever lane count or type changes; lanes matched across sections by position (ids renumber when a lane appears inside); zero width at a start or end means no predecessor / successor; an appearing lane is not linked to the original; a lane splitting into a turn pocket gets two successors. 1.9 §11.4, 11.6; 1.7 fig. 52, 56, 58, 60, 61
  2. Lane vocabulary per profile: curb, walking / sidewalk, restricted islands, @direction / bidirectional, access restrictions for bus and bike lanes, exit / entry / onRamp / offRamp. 1.9 §11.8, 11.10
  3. Road marks on each lane's outer edge, per country, laneChange explicit on solid lines, new-lane marks changing within the section as the lane opens. 1.9 §11.9; 1.7 fig. 64, 65
  4. Rework of the cross-section package (separate sidewalks, verges, fold-safe edges) on this model before it is committed.

3. Road geometry and height

  1. Annex D smoothness at every link, section boundary and connecting road (position, heading, height, roll; pitch recommended). 1.9 Annex D
  2. Superelevation, shape and cross-section surface never combined; reference frame never pitched; s and lengths plan-view. 1.9 §8.3, §10.5

4. Signals and objects

  1. Standard profile: lights at their physical position, stop lines as roadMark / signalLines objects with lane validity, light → stop line references, stop line → light dependencies, one controller per signal group listed by the junction, priority signs on incoming roads. Carla profile: signal at the stop line on the incoming road (1.7 placement) with signalReference on connecting roads. 1.9 §14; Guideline §9
  2. Objects: outlines with straight edges (enough corners on curves), length along the road, markings inside outlines, continuous repeats for barriers; objects on banked roads with zOffset including the bank. Header license for ODbL attribution (standard). 1.9 §13

5. Pedestrian and cycle network

  1. Pedestrian streets, footways, paths, steps and cycleways as walking / biking roads linked to the street sidewalks; delivery access where tagged; optional.

6. Speed

  1. Per-stage timing, then parallel per-road and per-junction stages with output byte-identical to the single-threaded run.
